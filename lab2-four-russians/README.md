# Лабораторная работа № 2 — метод четырех русских

**Вариант 2** — умножение бинарных матриц размера $N \times N$ над $\ \mathbb{Z}_2$ методом четырех русских (Four Russians, M4RM)

По условию $N = 2^n$, где $n \in \{3,4,5,6,7,8\}$, поэтому рассматриваются матрицы размеров $8$, $16$, $32$, $64$, $128$ и $256$

Цель работы — реализовать алгоритм, проверить правильность умножения и измерить зависимость времени выполнения от размера матрицы $N$ и размера блока $k$

Вместо SIMD-инструкций, из задания, используется упаковка бинарных элементов в `uint64` и побитовые операции Go — этот способ оптимизации согласован с преподавателем

## 1. Арифметика над $\ \mathbb{Z}_2$

Элементы матриц принимают значения $0$ или $1$

- Сложение выполняется по модулю $2$ и соответствует XOR (`^`), например $1+1=0$
- Умножение соответствует AND (`&`), поэтому произведение равно $1$ только для двух единичных множителей

Для $C = AB$ каждый элемент вычисляется по формуле

$$
C_{ij} = \bigoplus_{t=0}^{N-1} (A_{it} \land B_{tj})
$$

Знак $\oplus$ обозначает XOR, поэтому при умножении матриц над $\mathbb{Z}_2$ строки суммируются через XOR, а не через OR

## 2. Битовая упаковка матрицы

Вместо отдельного `bool` для каждого элемента используются 64-битные слова

```go
const bitsPerWord = 64

type bitWord = uint64

type matrix struct {
    size  int
    words int
    data  []bitWord
}
```

`size` хранит размер квадратной матрицы, `words` — количество машинных слов в строке, `data` — все строки подряд в одном срезе

Количество слов в строке вычисляется так

$$
w = \left\lceil \frac{N}{64} \right\rceil
$$

В коде

```go
wordsPerRow := (size + bitsPerWord - 1) / bitsPerWord
```

Матрица размера $256 \times 256$ занимает $256 \cdot 4 = 1024$ слова `uint64`, то есть $8192$ байта для данных без учета заголовка среза и самой структуры

```text
Строка матрицы 256 x 256:
[ uint64 ][ uint64 ][ uint64 ][ uint64 ]
   64 бит   64 бит   64 бит   64 бит

Массив data:
[ строка 0: 4 слова ][ строка 1: 4 слова ] ...
```

Биты в каждом слове нумеруются от младшего к старшему (LSB-first)

Столбец `0` соответствует биту `0` первого слова, столбец `63` — биту `63` первого слова, столбец `64` — биту `0` второго слова

Для элемента с индексами $(i,j)$ используются следующие вычисления

```go
wordIndex := j / bitsPerWord
bitOffset := j % bitsPerWord
dataIndex := i*m.words + wordIndex
mask := bitWord(1) << bitOffset
```

Например, элемент столбца $j=130$ находится в слове с индексом $2$ и бите с индексом $2$

В `matrix.go` реализованы следующие функции и методы

| Функция | Назначение |
| --- | --- |
| `newMatrix` | Создание нулевой квадратной матрицы |
| `getElement`, `setElement` | Чтение и изменение одного бита |
| `getRow` | Получение среза слов строки без копирования |
| `xorRows` | Побитовый XOR двух строк |
| `sumMatrix` | Сложение матриц над $\mathbb{Z}_2$ |
| `isEqual` | Сравнение двух матриц |
| `String` | Вывод матрицы в порядке возрастания индексов столбцов |

Операция XOR над двумя `uint64` обрабатывает одновременно $64$ пары элементов

## 3. Алгоритмы умножения

### 3.1. Скалярный алгоритм `stupidNaiveMultiply`

Три вложенных цикла вычисляют каждый элемент $C_{ij}$ по определению матричного произведения, перебирая все $N$ пар множителей

Временная сложность — $O(N^3)$, функция используется как независимая эталонная реализация при тестировании

### 3.2. Упакованное умножение `naiveMultiply`

Если $A_{ij}=1$, строка $B_j$ добавляется к строке $C_i$ через XOR

```go
for i := range n {
    resultRow := result.getRow(i)
    for j := range n {
        if a.getElement(i, j) {
            xorRows(resultRow, b.getRow(j))
        }
    }
}
```

При $w=\lceil N/64\rceil$ оценка числа машинных операций составляет $O(N^2w)$, или $O(N^3/64)$ для достаточно больших $N$ при фиксированном размере слова

Этот алгоритм используется для сравнения с Four Russians, поскольку оба работают с одинаковым представлением матриц

### 3.3. Метод четырех русских `fourRussiansMultiply`

Строки второй матрицы $B$ разбиваются на блоки длиной $k$

Для каждого блока предварительно строится таблица XOR-комбинаций его строк, после чего комбинация выбирается по соответствующим битам строки матрицы $A$

Для блока, начинающегося со строки `start`, фактическая длина равна

$$
r = \min(k, N-\mathrm{start})
$$

Алгоритм выполняет следующие действия

1. `buildLookupTable` создает $2^r$ комбинаций строк блока матрицы $B$, включая нулевую
2. `getBlockMask` извлекает $r$ битов из нужной строки матрицы $A$ и формирует индекс таблицы
3. Строка таблицы по этому индексу добавляется к соответствующей строке результата через XOR
4. Те же действия выполняются для остальных блоков матрицы $B$

Например, при $k=3$ маска `0b101` выбирает первую и третью строки текущего блока

$$
T[5] = B_{\mathrm{start}} \oplus B_{\mathrm{start}+2}
$$

В `buildLookupTable` каждая новая комбинация получается копированием уже построенной строки таблицы и прибавлением к ней одной строки матрицы $B$

`getBlockMask` извлекает биты с помощью сдвигов и маски без цикла по элементам, в том числе при переходе между двумя соседними `uint64`, например через столбцы `63` и `64`

Если $N$ не делится на $k$ без остатка, последний блок обрабатывается с уменьшенным значением $r$, без дополнения матрицы

Реализация принимает $1 \le k \le \min(N,16)$, верхняя граница ограничивает объем таблицы размером $2^k$ строк

### 3.4. Оценка сложности

Для строки матрицы требуется $w=\lceil N/64\rceil$ машинных слов, число блоков — $q=\lceil N/k\rceil$

Построение таблицы для одного блока требует $O(2^k w)$ машинных операций, обработка $N$ строк первой матрицы — $O(Nw)$

Общая оценка

$$
O\!\left(\left\lceil\frac{N}{k}\right\rceil (2^k+N)\left\lceil\frac{N}{64}\right\rceil\right)
$$

При увеличении $k$ число блоков уменьшается, но размер каждой таблицы растет экспоненциально, поэтому для конкретных размеров матриц значение $k$ подбирается по замерам

## 6. Измерение производительности

Замеры выполнены на Apple M1 под `darwin/arm64` для $N \in \{8,16,32,64,128,256\}$

Входные матрицы состоят из псевдослучайных битов с долей единиц около $50\%$, для каждого размера используется фиксированное начальное состояние генератора

Сравниваются `stupidNaiveMultiply` (`reference`), `naiveMultiply` (`packed_naive`) и `fourRussiansMultiply` при $k=1,\ldots,8$

Генерация входных матриц вынесена за пределы таймера, время включает выделение памяти под результат, вычисление произведения и для Four Russians построение таблиц

Каждая конфигурация измерена три раза, для сравнения используется медиана `ns/op`

В таблице приведены медианы трех запусков на Apple M1, для Four Russians указано минимальное время среди проверенных значений $k=1,\ldots,8$

Ускорение относительно упакованного наивного алгоритма вычисляется как

$$
S(N) = \frac{T_{\mathrm{packed\_naive}}(N)}{T_{\mathrm{Four\ Russians}}(N,k_{\mathrm{best}})}
$$

Если $S(N)>1$, метод четырех русских быстрее `packed_naive` для соответствующего размера матрицы

## 8. Выводы

На всех размерах $N=8,16,32,64,128,256$ результат Four Russians совпал с независимым скалярным умножением для проверенных значений $k$

При $N=8$ выигрыш от предварительно построенных таблиц отсутствует, медиана времени `packed_naive` составляет $350{,}8$ нс, а Four Russians при $k=3$ — $362{,}3$ нс

При $N=16$ Four Russians быстрее упакованного наивного алгоритма в $1{,}33$ раза, при $N=256$ — в $5{,}56$ раза

Лучшее значение $k$ среди проверенных равно $3$ для $N=8$, $4$ для $N=16,32$, $5$ для $N=64,128$ и $6$ для $N=256$

Полученные значения относятся к данной реализации, наборам входных матриц и процессору Apple M1, на другом оборудовании соотношение времени может измениться
