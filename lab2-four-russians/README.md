## Представление матрицы

Матрица хранится в битово-упакованном виде.

Так как элементы матрицы принадлежат \(\mathbb Z_2\), каждый элемент может принимать только значения `0` или `1`. Поэтому хранить каждый элемент как отдельный `bool` не обязательно — можно упаковывать несколько элементов в одно машинное слово.

В реализации используется тип `uint64`, то есть одно значение `uint64` хранит сразу 64 элемента строки матрицы.

Например, строка из 256 элементов представляется четырьмя значениями `uint64`:

```text
[ uint64 ][ uint64 ][ uint64 ][ uint64 ]
   64 бит    64 бит    64 бит    64 бит
```

То есть:

```text
64 + 64 + 64 + 64 = 256 бит
```

Количество `uint64`, необходимых для хранения одной строки, вычисляется как:

```go
words := (size + bitsPerWord - 1) / bitsPerWord
```

где:

```go
const bitsPerWord = 64
```

Структура матрицы имеет вид:

```go
type Matrix struct {
	size  int
	words int
	data  []uint64
}
```

Здесь:

- `size` — размер квадратной матрицы;
- `words` — количество `uint64`, приходящихся на одну строку;
- `data` — одномерный массив, в котором последовательно хранятся все строки матрицы.

Например, для матрицы `256 x 256`:

```text
size  = 256
words = 4
```

а длина `data` будет равна:

```text
256 * 4 = 1024
```

элементам `uint64`.

В памяти строки располагаются последовательно:

```text
data:

row 0        row 1        row 2
[ ][ ][ ][ ] [ ][ ][ ][ ] [ ][ ][ ][ ] ...
```

Для доступа к нужному `uint64` используется индекс:

```go
index := i*m.words + word
```

где `i` — номер строки, а `word` — номер 64-битного блока внутри строки.

Номер блока и номер бита внутри блока вычисляются так:

```go
word := j / bitsPerWord
bit := uint(j % bitsPerWord)
```

Например, для столбца `130`:

```text
word = 130 / 64 = 2
bit  = 130 % 64 = 2
```

То есть элемент находится в третьем `uint64`, в бите с индексом `2`.

Для чтения и изменения отдельных элементов используются методы:

```go
Get(i, j)
Set(i, j, value)
```

Такое представление позволяет выполнять побитовые операции сразу над 64 элементами матрицы и удобно для дальнейшей реализации алгоритма четырёх русских и SIMD-оптимизаций.
